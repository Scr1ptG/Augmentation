Раздел 2 · свой датасет

Зачем собирать свой датасет

Нет готового

Под вашу задачу часто нет датасета: сорта местных яблок, детали вашего завода, ваши комнатные растения.

Реальные условия

Готовые фото сняты «идеально». Сеть должна работать на вашей камере, при вашем свете и фоне.

Свои классы

Вы сами решаете, какие классы нужны и где граница между ними.

Контроль качества

Вы знаете, откуда каждая картинка и правильна ли метка. В чужих датасетах бывают ошибки разметки.

Весь цикл руками

Сбор, чистка, разметка, обучение, проверка — ровно то, что делают в реальных проектах.

Портфолио

Проект на собственных данных выглядит сильнее, чем очередной MNIST.

Главное

Качество модели ограничено качеством данных. Хорошая архитектура не спасёт плохой датасет.

Раздел 3 · resize

Почему обычного resize мало

Сеть принимает картинки одного размера, например 128 × 128. Если вертикальное фото сразу сжать в квадрат, объекты расплющатся.

Умная обрезка (smart_resize) работает в два шага:

  1. обрезать до нужных пропорций;
  2. уменьшить до нужного размера.

Если обрезать сверху, объект в центре кадра теряет низ. Поэтому режем посередине.

Раздел 5 · разбиение

Правильный порядок подготовки данных

  1. Собираем список путей к файлам и номера классов.
  2. Делим пути на train / val / test с stratify, чтобы доля классов везде была одинаковой.
  3. Создаём три Dataset: train с train_tf и синтетикой, val и test с val_tf.
  4. Оборачиваем в DataLoader: train с shuffle=True, остальные без перемешивания.
  5. Учим на train, после каждой эпохи смотрим val. Test — один раз в самом конце.

Так делать нельзя:

  • Сначала аугментация, потом split. Копии одного фото попадут и в train, и в test — утечка, метрика завышена.
  • ImageFolder + random_split с одним transform. Val тоже получит случайную аугментацию.
  • Подбирать эпохи и архитектуру по test. Test превращается во второй val.

Dataset: как отдать одну картинку

Dataset — это класс с двумя обязательными методами:

  • ①__len__ — сколько всего примеров.
  • ②__getitem__(i) — вернуть i-й пример: (картинка, метка).

Для «1 → 4» каждая картинка даёт k вариантов. Номер i превращаем в пару: какая картинка и какой вариант. Вариант 0 — оригинал.

Conv2d

Фильтры 3 × 3 ищут признаки: сначала края и пятна, глубже — формы и части объектов. Число каналов растёт.

MaxPool2d(2)

Уменьшает высоту и ширину в 2 раза. Сеть быстрее и меньше зависит от точного положения объекта.

Linear

Собирает признаки в ответ. Последний слой выдаёт логиты — по числу на класс, без softmax.

Формы в PyTorch: (каналы, высота, ширина). В батче впереди добавляется размер батча: (32, 3, 128, 128).

Раздел 7 · архитектура

Та же схема в коде (вариант A)

  • ①Сеть — класс-наследник nn.Module. Это аналог функционального API: сами описываем путь данных.
  • ②features превращает картинку в карту признаков.
  • ③classifier превращает признаки в ответ.
  • ④Dropout выключает часть нейронов при обучении.
  • ⑤На выходе логиты: softmax уже внутри CrossEntropyLoss.
  • ⑥forward — как данные идут через слои.
class Net(nn.Module):                               # ①
    def __init__(self, num_classes, in_ch=3):
        super().__init__()
        self.features = nn.Sequential(              # ②
            nn.Conv2d(in_ch, 32, 3, padding=1), nn.ReLU(),
            nn.MaxPool2d(2),                        # 128 → 64
            nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(),
            nn.MaxPool2d(2),                        # 64 → 32
            nn.Conv2d(64, 128, 3, padding=1), nn.ReLU(),
            nn.MaxPool2d(2),                        # 32 → 16
        )
        self.classifier = nn.Sequential(            # ③
            nn.Flatten(),                           # 128·16·16
            nn.Linear(128 * 16 * 16, 256), nn.ReLU(),
            nn.Dropout(0.3),                        # ④
            nn.Linear(256, num_classes),            # ⑤
        )

    def forward(self, x):                           # ⑥
        x = self.features(x)
        return self.classifier(x)

Берём батч и переносим на GPU

Раздел 8 · шаги ③ и ④

Прогоняем через сеть и считаем ошибку

  • ③model(images) вызывает forward. На выходе логиты: для каждой картинки по числу на класс. Чем больше число, тем сильнее сеть «за» этот класс.
  • ④CrossEntropyLoss сравнивает логиты с правильными метками и выдаёт одно число — среднюю ошибку на батче. Внутри он сам делает softmax.
Метки

Метки — номера классов (тип long), а не one-hot.

    outputs = model(images)             # ③ прямой проход
    # outputs: [32, NUM_CLASSES] — логиты
    # outputs[0] = tensor([ 2.1, -0.4,  0.3])
    #                        ↑ сеть «за» класс 0

    loss = criterion(outputs, labels)   # ④ ошибка
    # loss: tensor(0.8731) — одно число на весь батч
    # правильные ответы уверенно → loss маленький
    # ошибки уверенно → loss большой

Раздел 8 · шаги ⑤, ⑥ и ⑦

Три строки, которые учат сеть

⑤ zero_grad()

PyTorch складывает градиенты от вызова к вызову. Если не обнулить, к новым добавятся старые от прошлого батча, и сеть будет шагать не туда.

⑥ backward()

Обратное распространение ошибки. Для каждого веса считается градиент: в какую сторону его менять, чтобы loss уменьшился. Лежит в w.grad.

⑦ step()

Оптимизатор (Adam) сдвигает каждый вес на небольшой шаг против градиента. Размер шага задаёт lr.

optimizer.zero_grad()   # ⑤ стираем старые
loss.backward()         # ⑥ считаем новые
optimizer.step()        # ⑦ обновляем веса
Как запомнить

Спуск с горы в тумане: ⑤ забыть прошлый шаг, ⑥ нащупать, куда склон идёт вниз, ⑦ шагнуть туда. Порядок именно такой.

Раздел 8 · шаг ⑧

Метрики по loss и валидация

  • ⑧loss.item() — обычное число Python. Умножаем на размер батча: последний батч меньше, и так среднее будет честным.
  • ⑧outputs.argmax(1) — номер класса с наибольшим логитом. Сравниваем с метками и считаем верные.
Валидация

model.eval() выключает Dropout, torch.no_grad() не считает градиенты. Шаги ⑤–⑦ на val не делаем никогда.

    total += labels.size(0)

Раздел 8 · собираем вместе

Полный цикл обучения

Одна функция на train и на val: флаг train включает шаги ⑤–⑦ и градиенты.

history копит метрики по эпохам — из неё построим графики.

Получилось, если

loss train падает, а в каждой строке видны loss и accuracy для train и val.

def run_epoch(loader, train):
    model.train() if train else model.eval()
    total_loss, correct, total = 0.0, 0, 0
    with torch.set_grad_enabled(train):
        for images, labels in loader:                          # ①
            images, labels = images.to(device), labels.to(device)  # ②
            outputs = model(images)                            # ③
            loss = criterion(outputs, labels)                  # ④
            if train:
                optimizer.zero_grad()                          # ⑤
                loss.backward()                                # ⑥
                optimizer.step()                               # ⑦
            total_loss += loss.item() * labels.size(0)         # ⑧
            correct += (outputs.argmax(1) == labels).sum().item()
            total += labels.size(0)
    return total_loss / total, correct / total

history = {"train_loss": [], "val_loss": [], "train_acc": [], "val_acc": []}
for epoch in range(1, EPOCHS + 1):
    tl, ta = run_epoch(train_loader, train=True)
    vl, va = run_epoch(val_loader, train=False)
    for key, v in zip(history, (tl, vl, ta, va)):
        history[key].append(v)
    print(f"{epoch:2d} | loss {tl:.3f} / {vl:.3f} | acc {ta:.2f} / {va:.2f}")

Что делать при переобучении

Больше аугментации, Dropout, меньше эпох (остановиться на лучшей), сеть попроще.
